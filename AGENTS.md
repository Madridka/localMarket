# AGENTS.md

## Назначение

Этот репозиторий содержит frontend SPA маркетплейса «Рядом». Любое изменение должно сохранять единый сценарий разработки и границу, через которую позже подключится Express API.

## Обязательный сценарий работы

1. Прочитать `README.md`, `docs/architecture.md` и тесты затрагиваемого сценария.
2. Найти существующий domain/store/repository/component, прежде чем создавать новый слой или дублировать логику.
3. Вносить изменения по направлению `view/component → Pinia store → repository → adapter`.
4. Добавить или обновить i18n-ключи и тесты поведения.
5. Проверить затронутый сценарий вручную на desktop и mobile, если менялся UI.
6. Перед завершением обязательно выполнить `bun run check`.

## Архитектурные правила

- Использовать Vue SFC, Composition API и `<script setup lang="ts">`.
- Не обращаться к `localStorage` вне `src/services/storage.ts` и repository-адаптеров.
- Не выполнять `fetch` во views, компонентах или stores. Будущий HTTP-код должен реализовывать repository-интерфейсы.
- Не дублировать параметры каталога в Pinia: URL query является источником истины для фильтров.
- Не запрашивать геолокацию пользователя. Радиус считается от центра выбранного города; для объявления допустима только округлённая `LocationCell`.
- Не добавлять видимые пользователю строки вне `src/i18n` за исключением тестового/пользовательского контента и серверных справочников.
- Использовать существующие Tailwind/design tokens; не добавлять произвольные почти одинаковые цвета, тени и радиусы.
- Идентификаторы доменных сущностей внутри приложения — строки; legacy-числа нормализуются в адаптере.
- Не менять seed taxonomy ID без миграции сохранённых объявлений и теста совместимости.

## Команды

- `bun run dev` — локальная разработка.
- `bun run test` — Vitest в watch-режиме.
- `bun run test:run` — однократный запуск тестов.
- `bun run typecheck` — строгая проверка TypeScript/Vue.
- `bun run lint` — ESLint.
- `bun run format` / `bun run format:check` — Prettier.
- `bun run build` — production-сборка.
- `bun run check` — полный Definition of Done.

## Обновление контрактов

При изменении маршрутов, domain types, ключей хранилища или repository-интерфейсов одновременно обновлять `docs/architecture.md`, тесты миграции и README, если меняются команды или способ запуска.
